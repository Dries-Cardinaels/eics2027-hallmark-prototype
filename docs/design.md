# Visual design guidelines

Give the terrain map the largest share of the workspace. Keep the document header shallow and the inspector sidebar modest in width without reducing text or target sizes. Limits stay in a compact disclosure whose closed summary always shows both current thresholds. Keep the selected result near the top of the inspector. Keep Proposed path and Pipeline always visible: the route strip and processing graph are the core workflow, not optional disclosures. Retain an easy path-focus action and readable graph navigation. Combine the map legend and complete branched pipeline in one compact bottom dock with a single outer surface, border and shadow and a subtle internal divider. Avoid a redundant graph heading or stage caption; the selected node communicates the stage. Allow the legend to wrap and the graph to scroll horizontally without scaling its text, and reserve enough width for complete criterion labels. Lay out the dock and locator in normal flow so changing legend height cannot create collisions. The Limits disclosure retains its state through ordinary selections and limit edits.

Use pastel colours with clear, strong outlines and transparent fills. Source and context fills should keep the terrain visible underneath; retain them rather than reducing the interface to outlines alone. Current route cells use opaque pastel terrain-conforming patches for readability. Dark borders should be narrow bands around a region, never opaque dark backing across the whole cell. Source, route, map, legend and inspector encodings should agree.

Use pastel teal for within-limit results, peach for exceeded criteria, gray-blue for unavailable results, blue for declared height inputs, and violet for suspicious supplied quality. Separate quality from criterion outcomes: suspicious support is not an exceedance, error probability or safety classification. Preserve text, symbols and explicit missing/not-supplied states alongside colour. Use two independent, compact checked/unchecked controls: Height flags for supplied source flags and Affected results for derived dependency flags. Raw flags use a light violet hatch with a thin boundary. Affected results use a translucent tint with a clearly purple contour: approximately 2 CSS pixels over a pale 4-pixel halo, stable through zoom and resize. Keep the contour visible across opaque route patches while selected cells and exact blue source evidence retain priority. Both contexts share the richer opaque purple border; retain the subdued raw hatch and transparent context fills. Preserve explicit URL settings, including legacy flags=0 as both off. Use the same context styles in overview and trace. Blue footprints always identify exact queried support. Height flags controls all raw/source quality annotations, including traced purple fills and actual-height markers, raw badges, source-grid/table labels and their accessible text. Affected results controls derived support counts, path dependency markers/tracks, comparison counts and branch-card insights. Both off hides these insights without changing input support, supplied data, planner preference/costs or approval. Explicitly choosing Quality retains its category map/legend/hover without enabling either switch.

Show the selected result's flagged-input count beside Height here raw status/code so a supplied suspicious centre and zero suspicious calculation inputs are understandable together. An excluded Horn centre uses a neutral dashed non-input treatment and an inspectable context control. Purple is added only when its actual supplied height is flagged, respecting Height flags on the map. Never add excluded context to input counts, source indices or dependency navigation. Source records display supplied quality directly, rather than describing themselves as computational inputs.

Draw a contrasting boundary wherever adjacent categorical terrain results change, including within/exceeded/unavailable classes and supplied quality categories. Keep uniform regions free of a full cell grid. These category boundaries remain visible independently of the two quality-context toggles. Keep their screen width thin and approximately constant through zoom and resize, so they become less prominent relative to cells in close inspection rather than growing into thick bands. Continuous numeric maps retain their smooth colour scale; do not invent contour levels.

Use actual surface-conforming border meshes for source and path cell outlines when a wider outline is needed; WebGL line width is not a dependable way to thicken them. Categorical region boundaries use surface-conforming native one-pixel lines, without a fixed world-width backing band. The affected-result contour uses screen-space line geometry and a pale halo to remain distinct from these categorical boundaries. Aggregate overview region geometry so adding evidence visibility does not create one draw call per raster cell. Keep individual input marks available for exact hover and focus feedback.

Identify the selected native footprint with a contrasting double surface border and subtle fill. Keep the selected layer, native coordinates, cell dimensions and relevant path ordinal in the existing compact selection key and inspector. Do not add a floating screen-space square, permanent terrain callout or leader.

Make spatial scale explicit. Show native cell spacing separately from a ruler for horizontal ground distance in the current 3D view. The ruler must account for camera orientation, zoom and viewport changes, and disappear when its geometry cannot be defined. Ground distance is not surface distance or terrain-height difference. Display geometry must preserve delivered native spacing and true vertical scale.

A future vehicle model should use documented dimensions and true scale, and be labelled as a reference. A model, proposed centreline or illustrative vehicle footprint does not establish mission suitability, terrain clearance or operational validation. No rover or terrestrial robot asset is selected by this design update.


Keep route inspection easy to scan with aligned Slope and Roughness checks and a third supporting-height track scoped to the mapped derived branch: Slope inputs, Roughness inputs or combined Height inputs. Use the same scope for route ! markers, strip tooltips and comparison counts. Source height and quality maps omit derived markers, the dependency track and its comparison row; supplied raw flags stay independent. Label each row once, use one selectable column per crossed native cell, and keep the route count/native dimensions and selected index each in one place. Limit outcomes and suspicious dependencies need different symbols and colours. No supplied suspicious flags must not read as safe, and absent quality must say Not supplied. Respect pipeline stages: raw Slope and Roughness route patches and selected results use their quantitative value colours and numeric labels, without within/exceeded outcomes. Only Slope limit, Roughness limit and Assessment use check colours and outcome labels. Keep the planning strip's separate threshold rows explicitly labelled Slope limit and Roughness limit. Source terrain and quality maps retain combined assessment colours. A compact caption names this colour scope; the same shared selector keeps raw hover numeric and check-stage hover categorical. Browsing a branch must preserve the planner objective, route revision and approval; path picks keep the currently mapped stage.

Use identical full native bounds for selected results, source cells and crossed path cells. Do not inset one role into smaller squares that suggest a different resolution. Show a concise selected-one-cell size and, during tracing, the exact supporting native-cell count with a same-grid explanation. Explain that neighbouring inputs are not subdivisions and merged colour regions are not large cells. Keep this explanation compact; zoom changes the view, never the delivered measurements or resolution.


Apply the same visual hierarchy to the proposed path: opaque pastel terrain-conforming native-cell patches, strong narrow borders, a clear selected footprint, and stronger exact height inputs during tracing. Use only small technical offsets to prevent drawing conflicts; never extrude route cells or suggest increased terrain height. During tracing, keep a muted solid current-route centreline and subdued contextual route cells outside exact queried source footprints. The previous route remains dashed slate. Preserve the selected result's active-stage colour, quantitative before limit checks and categorical at check stages, with a contrasting selection border. When its centre is an actual height input, retain a visible blue input border and source hatch, with the compact Centre included label matching Height here; suspicious source evidence remains purple. An excluded Horn centre keeps neutral dashed context and never becomes an input. Suppress route dependency sprites during tracing so only actual suspicious source heights receive raised flags. Do not confuse suspicious path dependencies with suspicious individual source heights.

Keep hover readouts transient and place them using their measured bounds and the projected bounds of visible flags, exact traced support cells and control surfaces. Prefer stable nearby positions; hide a hover readout when no unobstructed slot exists. Recompute placement after orbit, zoom and resize without moving terrain cells. Permanent selection details remain in the compact selection key and inspector.

Keep planning controls in the existing Proposed path section: start and goal picks, an explicit Plan action, and a compact Draft / Needs review / Approved state with local approval. Put the cost formula, optional quality preference, breakdowns and exclusion addresses in a compact Plan policy disclosure. Planning-input changes clear obsolete routes and approval; missing paths must not leave stale clickable geometry. Endpoint picking takes precedence over path inspection. Start/goal markers and excluded native cells share the terrain's actual spacing and footprint. Preserve the always-visible assessment strip and pipeline and the existing evidence hierarchy during tracing.

When revising a plan, retain one previous successful route as nonselectable dashed slate-blue context, with faint pastel fills and dashed outer boundaries only for its unique native cells. Keep the current route and exact source evidence dominant and never duplicate quality markers for history. A compact three-row Previous/Proposed comparison counts slope exceedance, roughness exceedance and route cells with suspicious combined input support; show each native cell population and assess both at current limits. Keep missing quality explicit, distinguish matching paths, and frame the union with Focus. Historical approval must remain visibly and structurally separate from current approval.
