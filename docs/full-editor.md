# Full editor (outside the paper configuration)

This document describes the editor opened without `?paper=1`: route planning, the RMS review threshold, the Earth cases and the auxiliary layers. The paper configuration and the shared inspection features are described in the [README](../README.md). Nothing here is shown or claimed in the paper.

## Interaction

- Assessment maps cells within the configured slope and height spread limits, exceeded cells, and incomplete results. Slope (°) and Height spread (m) are calculated-value stages (height spread has the internal id `roughness`). Slope limit and Height spread limit are separate check stages, selected directly in the map menu or graph. The compact Limits summary lists the limits that are set, or reads "Not set" when neither is; Earth cases open with both limits unset, and the lunar cases with the scenario settings below; expand it to edit the existing number and slider controls, which update the map, counts and selected record together. Limits are configured numerical criteria; no vehicle capability or safety validation is implied.
- Calculated values use a continuous numeric scale. Limit checks use within/exceeded/incomplete classes and display the outcome first, followed by the input-to-limit comparison. Graph value nodes carry units; pill-shaped check nodes carry ≤. Equality remains within the limit. Older quantity-plus-mode links normalize to these explicit stages.
- **Proposed path** runs a compact supervisory loop. Pick **Set start** and **Set goal**, then **Plan**. Deterministic four-neighbour A* proposes a route between native cells. **Needs review** means the current proposal can be inspected; **Approve** records review of that exact revision and sends no robot command. Endpoint, active criterion or exclusion edits clear the current route and approval and return to **Draft**. Explicit planning-branch or flag-switch changes automatically replan an existing proposal, retain its previous route/settings and clear approval. **Exclude row, col** blocks the selected native cell; plan again to revise, or **Clear** exclusions. Missing inputs required by the active branch are blocked.
- **Planning** names the active branch separately from inspection. Processing map-menu or pipeline selections set it. The supplier Height RMS and LOLA returns per cell maps preserve it. Heights uses available native heights and ground distance; Slope and Height spread use baseline plus only their scaled value; their limit stages additionally apply their own exceeded-limit penalty. Assessment and Traversal cost use both values and both checks. Input tracing, returning through evidence, route-cell selection and the auxiliary Flagged input fraction layer preserve the planning branch. The URL retains that branch separately from the inspected map. Inactive limits can be edited without invalidating the route or approval.
- **Route objectives** shows the two priorities when supplied flags are selected: first minimize the number of matching native route cells, then minimize terrain cost (ground distance for Heights). **Height flags** matches a route cell's own supplied flagged height. **Affected results** matches any flagged height used by the active planning branch, using eight neighbours for slope or the 25-cell height spread/combined union. Both switches form a union and count each cell once, including start and goal. Neither switch selects terrain-only planning. Unknown quality stays unknown and falls back to terrain-only planning. Affected results is inapplicable to Heights, with its setting retained for later derived branches. Flags add no numerical penalty to terrain density. The Traversal cost map colours the terrain tie cost; selected-cell matching is reported separately.
- The always-visible **Evidence** row opens **Flagged input fraction**, which reports suspicious / total unique combined height inputs. It is auxiliary evidence and does not change the planning branch. **Focus ↗** frames the current and previous route. The strip shows only the active planning branch's values/checks and an independent matching-cell track when selected. A compact Previous/Proposed comparison evaluates both geometries under the current branch, switches and active limits, while historical settings remain in the export. Unavailable historical geometry has no finite current cost. Matching geometries remain explicit. Only the current proposal is selectable; the previous route is context. This centreline is not a vehicle footprint; see [the planner and inspection note](proposed-path.md).
- **Height flags** also shows supplied suspicious height cells with a violet hatch and controls raw/source quality annotations. **Affected results** also marks displayed derived results that depend on suspicious inputs. The displayed overlay may follow an inspected branch while planning stays fixed. Actual route ! markers and match counts follow the planning branch and switches. Both off hides quality details while preserving blue source support, values and checks; explicitly selected quality views retain their own evidence. A suspicious centre can be excluded from Horn slope while being included in height spread. Nuugaatsiaq uses the original ArcticDEM mask bits; matchtag remains separate categorical evidence.
- **Height here** shows the raw supplied status/code at the selected location alongside the selected result's input-flag count. It states whether that height is used or the Horn centre is excluded. The excluded centre remains inspectable through a neutral dashed context cell; it is never added to the eight actual slope inputs. Its control navigates directly to Heights without creating a dependency edge. Traced inputs retain stronger blue outlines regardless of visibility; purple fills and raised ! markers for suspicious actual inputs follow Height flags.
- Select one result by clicking the terrain or using arrow keys on the canvas. A contrasting terrain-conforming cell border identifies the selection. The compact map selection key and inspector show its layer and native address, with the path ordinal when relevant. Hovering transiently previews the cell and mapped value; its readout avoids visible raised flags, traced support cells and map controls. Source-cell footprints are hidden until inspection.
- Choose a processing step directly in the always-visible **Pipeline** graph; its selected node shows the stage. The legend and complete graph share one compact dock. The physical location stays fixed across source and analysis grids.
- Expand the producing method to inspect its calculation and parameters.
- Open a branch card to map that criterion. Continue upstream through its input and height grid; the branch map stays visible as context while the inspector and source marks follow the input. The inspection path returns to earlier results. A new map click selects the mapped quantity again.
- Trace inputs reveals the exact supporting cells and focuses the camera. Blue footprints are the native height cells used by the selected calculation, not a refinement of the selected result cell. The input header gives their native spacing. Path, selected result and source footprints all use the same full native cell bounds: 4 × 4 m at Nassau, 5 × 5 m at Connecting Ridge, 2 × 2 m at Nuugaatsiaq, and the selected survey spacing at Blatten. A slope trace shows eight neighbouring native height cells; height spread and combined use 25, not subdivisions of the selected result. Zoom changes only the camera. Top preserves focus; Overview hides the support and restores the complete chunk. A north-up locator uses the delivered heights, retains the selected location, and allows picking elsewhere in the same crop.
- Change either limit with its slider or number field. Outcomes update; heights, derived values and dependencies remain unchanged. The URL retains both limits (an absent value means unset), both flag switches, the current view and the separate planning branch. Older flags=0 links default both contexts off.
- The spatial input grid mirrors the actual 3 × 3 or 5 × 5 support. Hover or keyboard-focus a height to emphasize its exact 3D source mark; click to navigate upstream. Excluded cells are inert.
- Export the selected Hallmark query with its source and result grids, separately labelled height-here context, independent context settings, current route and assessments, exact planning endpoints/exclusions/limits/branch/flag settings/objectives/revision, and any approval of that same route. Exports separate the current and previous plan; previous parameters and any approval remain historical. A Draft or failed plan exports no current route or approval, while retaining the previous context and comparison at the current limits.

Drag to orbit, scroll to zoom, and right-drag to pan. Keyboard shortcuts: F focuses inputs, Shift-F fits, and T gives a top view.

All visible cell addresses use the starting height grid. Exported queries retain each operation's own grid coordinates.

## Lunar evidence inspection

Without `?paper=1`, Nassau is the default case, including absent or unrecognized case parameters. Existing `case=moon` links still open it. Our proposed rover routes are illustrative, not actual mission routes. Knowledge laundering is treating supplied terrain information as reliable while the supplier's own traces of its origin qualify it, because processing (heights → slope / height spread → cost → route) drops those qualifications. The default 15° slope and 0.15 m height spread limits are scenario settings, not rover requirements.

Nassau's supplier cell codes mean: **0** NoData/outside boundary; **1** Shadowed; **2** Saturated; **3** Suspicious (edge, corner, did not correlate, etc.); **4** Interpolated/extrapolated (e.g. from neighbouring pixels); **10–14** Successful correlation; **15** Manually edited. The map legend groups 10–14, while source cells and export retain the actual code. Successful correlation does not guarantee accuracy, and unknown earlier history is separate from quality. The Source disclosure links the retained producer README. Height flags and Affected results continue to use only real code 3 for Nassau.

[Connecting Ridge](http://127.0.0.1:8772/editor/?case=connecting-ridge) opens the **Height RMS (m)** source map with slope planning. **LOLA returns per cell** is a separate source map. **Show height RMS map / Hide evidence map** and choosing a numeric source map preserve the current result, declared inputs, route, approval and planning branch. Picking the map inspects the corresponding native height with its supplied evidence. Numeric maps use continuous scales, with unknown evidence distinct from zero; they add no suspicious categories or automatic planning priorities.

**RMS review (m)** is an optional operator threshold, initially unset and shown only when height RMS is supplied. Enter a finite nonnegative value to mark raw heights whose unrounded supplied RMS is strictly greater than that value; equality does not trigger. The violet source hatch and affected-result boundaries follow exact declared support of the displayed branch, while route markers and the **Review** row follow the persistent planning branch. The inspector counts triggering supporting heights, lists inspectable triggering cells, and reports unknown RMS separately. Review annotations remain on heights, source evidence, calculated maps and Trace inputs; continuous RMS values are retained. Clear removes the rule and its annotations. The URL parameter `rmsreview` preserves the entered value, including zero; its absence means unset. This rule is an operator choice, distinct from Nassau’s supplier code 3, and never changes route geometry, terrain costs, planning priorities, revision or local approval. Manual exclusion and replanning remain available.

The inspector separates supplier height RMS at the current cell from **Input height RMS**, the minimum–maximum and known/total coverage over the exact queried support. Horn slope uses eight neighbours and excludes its centre; height spread and traversal cost use the 25-cell union. These ranges are source evidence summaries, not propagated output RMS. The route strip also shows **Max input RMS (m)** for every crossed cell using the fixed planning branch’s exact declared support. On the Height RMS map, route cells use this maximum on the same continuous scale as the native-height background. **Inspect largest RMS** in the path heading selects the route cell with the largest known maximum and traces its planning-branch inputs; it ranks source evidence only and leaves cost, limits and approval unchanged. The inspector’s **Inspect largest RMS** opens the actual supporting height cell; its breadcrumb returns to the selected result. Ties are labelled and the first cell in grid order is selected. **Largest RMS** identifies the maximum sources in the input grid and source table. Nassau’s supplied categorical codes select flagged heights (code 3) and affected results as binary sets; Connecting Ridge retains its continuous numeric colour scale and coverage. Its optional operator review rule adds display annotations without an RMS cost term. Derived uncertainty remains **Not estimated** in both cases. Incomplete coverage is marked with hatching and an asterisk; unknown values are never treated as zero. Source cells show compact values with unrounded values in tooltips and query/export. The LOLA count is the supplier's number of LOLA returns per cell. A count of 0 reads "no LOLA return": the height is still supplied, and the supplier states only that empty pixels are filled by interpolation, without naming the donors. Height RMS and counts never alter terrain values, cost or planning.

The retained NASA GeoTIFF window has no resampling, reprojection, scaling or synthetic uncertainty. Preparation verifies all three native array hashes offline. Acquisition date is not supplied; the product's reference paper is Barker et al. (2021), and the fixture was retrieved on 5 November 2026. ## Earth cases

Open [the Blatten example](http://127.0.0.1:8772/editor/?case=blatten). Choose a route cell and expand **Height comparison** to inspect both surveys at its physical position. Switch **Heightmap** to plan on the other survey. The post-event 400 × 400 cell crop preserves measured raster values, including surface objects. The 2024 product gives bare-ground elevations. Model alignment and different surfaces limit the interpretation of a height difference. All cells in both crops contain heights; subsurface water, bearing strength, per-cell accuracy and authorized search boundaries are outside the supplied evidence. See [mission and survey evidence](../../demo/research/blatten-rescue-evidence.md) and [event crop sources and licence](../fixtures/earth/blatten-event/README.md).

Open [the Nuugaatsiaq example](http://127.0.0.1:8772/editor/?case=earth). The 17 June 2017 landslide tsunami prompted evacuation and searches under continuing danger. This is a retrospective proposal for a rover to inspect the southern settlement peninsula, not a documented deployment, operational benefit or rescue route. Knowledge laundering is the danger of losing supplied qualifications through heights → slope / height spread → cost → route. **Inspect flagged route inputs** selects an affected interior route cell: trace its source heights, exclude a cell and replan before approving the revised scenario. **Scenario & source context** expands the incident and processing qualifications; the two familiar Nassau switches control raw height evidence and affected results.

The initial route has 76 native cells from (110, 100) to (165, 80), checked against the published settlement maps and retained OpenStreetMap coastline. The planner is not constrained to a surveyed road or clearance polygon. With both flag priorities selected it includes three cells matching the own-height / slope-input union, including the goal’s cloud-flagged height of 28.96875 m. All eight Horn inputs at that goal have cloud bit 4 and matchtag 1; the height under the result is excluded from the slope’s declared support. Height spread includes that centre in its 25-cell footprint. The full crop contains 18,412 cloud flags, 656 water flags (all combined with cloud), and 4,758 matchtag-zero cells.

ArcticDEM is a surface model that includes buildings and other objects. Mask bits 1=edge, 2=water and 4=cloud are retained exactly, including combinations; zero means no supplied mask flag. Matchtag 1=stereo matched and 0=interpolated is separately inspectable and does not establish physical observation, accuracy or calibrated uncertainty. The planning switches prioritize the supplied bitmask only, using the existing lexicographic count before terrain cost; matchtag adds no invented numerical penalty. Source arrays and query evidence survive visibility changes. Heights use illustrative elevation shading because no public ortho asset is supplied in the retained STAC item.

The imagery dates to 19 June 2017. Constituent scene processing dates are in 2018, the strip was created in 2021, and packaging/publication occurred in 2022. Operational availability of this DEM in 2017 is not established. The archived Atami fixture uses a continuous display surface across cells with zero ground returns. With the gap overlay off, the Heights view interpolates colour from surrounding measured cells. The overlay reveals gaps and their effects. Numerical branches read the selected survey’s working grid. Materials, cutaway sides and the flat base are illustrative. The planner minimizes selected matching-cell counts first and the active branch's terrain cost second over four-neighbour native cells. The editor includes no illumination workflow, vehicle model or robot commands, and makes no claim of operator benefit. It compares two things only: the previous and proposed route (`editor/route-comparison.js`) and, at Blatten, the two surveys at one position (**Height comparison**).

A dynamic ground-distance ruler measures horizontal distances using camera-ray intersections with a horizontal plane. It updates with orbit, zoom and resize and hides when the intersections are undefined. It does not measure surface distance or terrain height. Native cell spacing remains separately visible. The selected surface border follows the actual native-cell footprint; the compact selection key retains its address.

Quantitative value maps use unlit materials so display lighting cannot change the colour scale. Categorical limit maps use shaded terrain while retaining their discrete classes. A known exceeded branch stays visible when another branch is missing, with an independent incomplete pattern. Texture samples use nearest-cell lookup; extra texture pixels only draw patterns and never create additional terrain measurements. Missing results and the analysis margin have a separate pattern. Translucent quality-region fills and contrasting boundaries report a property of the supporting heights, not a quality category or calibrated uncertainty assigned to the calculated value. Quality presentation is separate geometry and does not overwrite numeric map colours. The existing texture-painter hatching option remains available for other consumers.
